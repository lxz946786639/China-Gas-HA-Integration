# 中国燃气 Home Assistant 集成设计文档

## 1. 目标

基于 `doc/参考信息.md` 中的 Node-RED 流程，设计一个 Home Assistant 自定义集成：

- 集成中文名称：中国燃气
- 集成英文名称：China Gas
- Home Assistant domain：`china_gas`
- 获取燃气账号基本信息
- 获取月度账单信息
- 支持多账号配置：用户可手动添加多个 China Gas 集成实例，每个实例对应一个燃气账号
- 初期仅做数据查询，不提供缴费、开阀、改密等写操作

## 2. 参考流程摘要

Node-RED 流程的查询链路如下：

1. 初始化节点写入用户配置和固定请求头字段。
2. 调用注册/埋点接口：
   `POST https://zrds.95007.com/tracking/buriedPointEvent/add`
3. 调用 token 检查接口：
   `POST https://zrds.95007.com/wisdom/auth/checkMasInfo`
4. 生成时间戳 `timeStamp`。
5. 使用 `MD5(custCode + secretKey + timeStamp)` 生成 `signature`。
6. 调用账号基本信息接口：
   `POST https://zrds.95007.com/crm_controller/user/findCustInfoByCustCodeAndCustName`
7. 调用月度账单接口：
   `POST https://zrds.95007.com/crm_controller/payfee/getCustomerMoneyList`

Node-RED 定时周期为 `21600` 秒，即 6 小时。集成默认刷新周期建议沿用 6 小时，并允许用户在集成配置中设置。

## 3. 用户配置项设计

### 3.1 初始化节点字段映射

| Node-RED 字段 | 集成配置字段 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `custCode` | `cust_code` | 是 | 无 | 燃气编号/客户编号，每个燃气账号唯一。 |
| `custName` | `cust_name` | 是 | 无 | 用户名，按小程序实际值填写，可能包含脱敏星号。 |
| `userId` | `user_id` | 是 | 无 | 小程序用户 ID，用于请求头和埋点请求体。 |
| `accessToken` | `access_token` | 是 | 无 | 小程序 token，过期后需要用户更新。 |
| `x-mas-app-info` | `x_mas_app_info` | 是 | 无 | 小程序环境信息，请求头必需。 |
| `Referer` | `referer` | 是 | `https://servicewechat.com/<WECHAT_APP_ID>/<APP_VERSION>/page-frame.html` | 小程序 Referer。版本变化时允许用户覆盖。 |
| `accessFrom` | `access_from` | 否 | `yphpaymp` | 来源标识。默认取参考流程值。 |
| `secretKey` | `secret_key` | 否 | `<SIGNATURE_SALT>` | 签名盐值，来自小程序 JS。作为高级配置保留覆盖能力。 |
| `User-Agent` | `user_agent` | 否 | 参考流程中的微信小程序 UA | 高级配置。通常不需要用户填写。 |

集成自有配置项：

| 配置字段 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 否 | `{cust_code}-{cust_name}` | 当前集成实例显示名称。用户不填写时自动生成。 |
| `update_interval_minutes` | 否 | `360` | 配置界面中的刷新周期，单位分钟。 |
| `update_interval` | 否 | `21600` | 内部保存的刷新周期，单位秒。 |
| `bill_months` | 否 | `12` | 月度账单查询月数，配置区间为 2-12。 |

### 3.2 多账号配置方式

采用“单集成实例对应单个燃气账号”的设计。多账号不在同一个配置项中维护账号列表，而是由用户在 Home Assistant 中重复添加 China Gas 集成实例实现。

单个配置项结构：

```yaml
name: "<CUST_CODE>-<CUST_NAME>"
cust_code: "<CUST_CODE>"
cust_name: "<CUST_NAME>"
user_id: "<USER_ID>"
access_token: "******"
access_from: "yphpaymp"
x_mas_app_info: "<X_MAS_APP_INFO>"
referer: "https://servicewechat.com/<WECHAT_APP_ID>/<APP_VERSION>/page-frame.html"
secret_key: "<SIGNATURE_SALT>"
update_interval: 21600
bill_months: 12
```

设计理由：

- 符合 Home Assistant 常见模式：一个 config entry 管理一个外部账号或一组同源设备。
- 用户添加第二个燃气账号时，只需要再次添加 China Gas 集成。
- 每个实例独立保存 token、请求头和刷新状态，互不影响。
- 每个实例以 `user_id + cust_code` 作为唯一键，防止重复添加同一个燃气账号。

### 3.3 配置流程

初始配置流程：

1. 用户添加 China Gas 集成。
2. 第一步填写当前燃气账号的必填项，默认展开：
   - 燃气编号 `cust_code`
   - 用户名 `cust_name`
   - 用户 ID `user_id`
   - token `access_token`
   - 签名盐 `secret_key`
   - 应用身份标识 `x_mas_app_info`
3. 第一步的高级选项默认收起，并提供默认值：
   - 账号显示名称 `name`，不填时默认 `{cust_code}-{cust_name}`
   - Referer `referer`
   - `access_from`
   - `user_agent`
   - 月度账单查询月数 `bill_months`，范围 2-12
4. 第一步提交后立即调用 token 检查和账号基本信息接口。
5. 第二步配置刷新周期 `update_interval_minutes`，单位分钟，默认 360 分钟。
6. 查询成功并配置刷新周期后创建配置项，内部将分钟转换为秒保存到 `update_interval`。

选项流程：

- 修改当前实例的账号显示名称
- 更新当前实例的 token/小程序环境信息
- 修改当前实例的刷新周期
- 修改当前实例的月度账单查询月数

如需添加其他燃气账号，用户再次添加 China Gas 集成实例。

## 4. API 客户端设计

### 4.1 请求头

当前集成实例使用当前账号配置构造请求头：

```python
headers = {
    "Host": "zrds.95007.com",
    "Connection": "keep-alive",
    "xweb_xhr": "1",
    "accessToken": account.access_token,
    "x-mas-app-info": account.x_mas_app_info,
    "accessFrom": account.access_from,
    "User-Agent": account.user_agent,
    "userId": account.user_id,
    "platform": "mp-weixin",
    "Accept": "*/*",
    "Sec-Fetch-Site": "cross-site",
    "Sec-Fetch-Mode": "cors",
    "Sec-Fetch-Dest": "empty",
    "Referer": account.referer,
    "Accept-Encoding": "gzip, deflate, br",
    "Accept-Language": "zh-CN,zh;q=0.9",
}
```

`Content-Type` 按接口单独设置：

- 埋点接口：`application/x-www-form-urlencoded`
- token 检查接口：`application/json`
- 查询接口：`application/x-www-form-urlencoded`

### 4.2 埋点接口

接口：

```text
POST /tracking/buriedPointEvent/add
```

请求体：

```text
appUseType=0&clickType=3&eventType=1&channelType=0&userId={user_id}
```

成功判定：

```json
{
  "status": 1,
  "message": "请求成功"
}
```

如果埋点失败，不直接创建实体；配置流程中提示“初始化请求失败”。运行期更新失败时记录警告并进入重试。

### 4.3 Token 检查接口

接口：

```text
POST /wisdom/auth/checkMasInfo
```

请求体：

```json
{}
```

成功判定：

```json
{
  "message": "token有效"
}
```

失败处理：

- 配置流程中阻止保存，并提示用户更新 `access_token`、`x_mas_app_info`。
- 运行期标记该账号不可用，实体状态变为 `unavailable`。
- 创建 Home Assistant repair issue，提示重新配置 token。

### 4.4 签名生成

签名逻辑：

```python
time_stamp = int(time.time() * 1000)
signature = md5(f"{cust_code}{secret_key}{time_stamp}")
```

注意：

- `timeStamp` 字段名保持接口原样大小写。
- `signature` 使用 32 位小写 MD5。
- 账号基本信息和月度账单信息共用同一套签名逻辑。

### 4.5 账号基本信息接口

```text
POST /crm_controller/user/findCustInfoByCustCodeAndCustName
```

- `payload.status == "1"` 或 `payload.status == 1`

### 4.6 月度账单接口

接口：

```text
POST /crm_controller/payfee/getCustomerMoneyList
```

请求体：

```python
{
    "custCode": account.cust_code,
    "custName": account.cust_name,
    "startTime": start_yyyymm,
    "endTime": end_yyyymm,
    "timeStamp": time_stamp,
    "signature": signature,
}
```

时间范围：

- 默认查询最近 12 个月。
- `startTime` 和 `endTime` 格式为 `YYYYMM`。
- 使用 Home Assistant 本地时区计算月份。

成功判定：

- `payload.data` 存在，或接口直接返回账单对象。

- `payGasCheckList` 为空时不报错，实体显示无账单。

| `timeLastRecord` | 上次抄表日期 | 最新账单属性 |
| `lastRecord` | 上次读数 | 最新账单属性 |
| `timeCurRecord` | 本次抄表日期 | 最新账单属性 |
| `curRecord` | 本次读数 | 最新账单属性 |
| `curQty` | 本期用气量 | 最新用气量传感器，单位 m³ |
| `totalFee` | 总费用 | 最新账单金额传感器，单位 CNY |
| `gasFee` | 气费 | 最新账单属性 |
| `laterFee` | 滞纳金 | 最新账单属性 |
| `isPay` | 支付状态 | 最新账单属性 |

## 5. Home Assistant 实体设计

### 5.1 设备模型

每个燃气账号创建一个 Home Assistant device：

- identifiers：`(china_gas, f"{user_id}_{cust_code}")`
- manufacturer：`China Gas`
- name：用户配置的 `name`，默认 `{cust_code}-{cust_name}`
- model：返回的 `meterFormName` 或 `meterFormCode`
- serial_number：返回的 `meterNo`
- suggested_area：不自动设置，避免地址隐私泄露

### 5.2 传感器实体

每个账号默认启用的实体：

| 实体 key | 名称 | 状态来源 | 单位 | device_class | state_class |
| --- | --- | --- | --- | --- | --- |
| `balance` | 余额 | `countMoney` | CNY | monetary | measurement |
| `new_balance` | 最新余额 | `newCountMoney` | CNY | monetary | measurement |
| `owe_money` | 欠费金额 | `oweMoney` | CNY | monetary | measurement |
| `latest_bill_fee` | 最新账单金额 | 最新账单 `totalFee` | CNY | monetary | measurement |
| `latest_bill_usage` | 最新账单用气量 | 最新账单 `curQty` | m³ | gas | measurement |
| `latest_bill_month` | 最新账单月份 | 最新账单 `recordMonth` | 无 | 无 | 无 |
| `last_12_months_usage` | 最近 12 个月总用气量 | 最近 12 个账单月份 `curQty` 汇总 | m³ | gas | measurement |
| `last_12_months_fee` | 最近 12 个月总费用 | 最近 12 个账单月份 `totalFee` 汇总 | CNY | monetary | measurement |
| `average_monthly_usage` | 月均用气量 | 最近 12 个账单月份总用气量 / 实际账单月份数 | m³ | gas | measurement |
| `average_monthly_fee` | 月均费用 | 最近 12 个账单月份总费用 / 实际账单月份数 | CNY | monetary | measurement |
| `last_record` | 最近表底数 | `lastRecord` | m³ | gas | total_increasing |
| `last_record_date` | 最近抄表日期 | `lastRecordTime` | 无 | date | 无 |
| `qty_balance` | 剩余气量 | `qtyBalance` | m³ | gas | measurement |
| `max_gas` | 最大购气量 | `maxGas` | m³ | gas | measurement |
| `award_money` | 补贴金额 | `newAwardMoney` / `awardMoney` | CNY | monetary | measurement |
| `agent_money` | 代理金额 | `newAgentMoney` / `agentMoney` | CNY | monetary | measurement |
| `company` | 燃气公司 | `compName` | 无 | 无 | 无 |
| `address` | 地址 | `address` | 无 | 无 | 无 |
| `mobile` | 电话 | `mobile` | 无 | 无 | 无 |
| `gas_meter` | 燃气表 | `meterFormName` | 无 | 无 | 无 |
| `customer_type` | 客户类型 | `custType` | 无 | 无 | 无 |

默认禁用的诊断类实体：

| 实体 key | 名称 | 状态来源 | 说明 |
| --- | --- | --- | --- |
| `customer_status` | 客户状态 | `custStatus` | 诊断实体。 |
| `meter_status` | 表具状态 | `feeFlag` / `custStatus` | 诊断实体。 |

主余额传感器属性建议包含：

```yaml
cust_code: "<CUST_CODE>"

```

燃气表传感器属性建议包含原始字段名：

```yaml
meterNo: "<METER_NO>"
metertype: "01"
meterFormCode: "<METER_FORM_CODE>"
meterSeq: "<METER_SEQ>"
```

月度账单实体属性建议包含：

```yaml
bills:
  - record_month: "<YYYYMM>"
    time_last_record: "<YYYYMMDD>"
    last_record: "<LAST_RECORD>"
    time_cur_record: "<YYYYMMDD>"
    cur_record: "<CURRENT_RECORD>"
    current_quantity: "<CURRENT_QUANTITY>"
    total_fee: "<TOTAL_FEE>"
    gas_fee: "<GAS_FEE>"
    later_fee: "<LATER_FEE>"
    is_pay: "2"

query_start_month: "<YYYYMM>"
query_end_month: "<YYYYMM>"
```

属性中的账单列表需要限制长度，默认保留最近 12 个账单月份内的明细记录，避免实体状态过大。

### 5.4 账单统计规则

账单统计传感器基于规范化后的 `bills` 计算：

- 以 `record_month` 为账单月份。
- 取最近 12 个有账单数据的月份。
- 如果同一个 `record_month` 存在多条账单，先按月份汇总 `current_quantity` 和 `total_fee`。
- 最近 12 个月总用气量为这些月份的 `current_quantity` 总和。
- 最近 12 个月总费用为这些月份的 `total_fee` 总和。
- 月均用气量为总用气量除以实际账单月份数。
- 月均费用为总费用除以实际账单月份数。
- 当无有效账单时，统计传感器状态为 `unknown`。

统计传感器属性建议包含：

```yaml
months_count: "<MONTHS_COUNT>"
start_month: "<YYYY-MM>"
end_month: "<YYYY-MM>"
source_bill_count: "<SOURCE_BILL_COUNT>"
```

实体唯一 ID：

```text
china_gas_{user_id}_{cust_code}_{entity_key}
```

账号唯一 ID：


## 6. 数据刷新与协调器

每个配置项创建一个 `ChinaGasDataUpdateCoordinator`，每个 coordinator 只负责当前配置项中的单个燃气账号。

刷新流程：

1. 读取当前配置项的账号配置。
2. 按顺序执行：
   - 埋点初始化
   - token 检查
   - 获取账号基本信息
   - 获取月度账单信息
3. 保存当前账号的最新结果：

```python
{
    "customer": {...},
    "bills": [...],
    "last_update": "...",
    "available": True,
}
```

刷新周期：

- 从当前集成实例配置 `update_interval` 读取。
- 默认值为 `21600` 秒，即 `timedelta(hours=6)`。

执行策略：

- 单个实例内请求保持顺序执行，因为 token 检查和签名依赖初始化上下文。
- 多个燃气账号由多个 config entry 各自刷新，依赖 Home Assistant 对不同配置项的调度。
- 不在本集成内部维护跨实例并发队列；如后续发现接口限流，再增加 domain 级别的全局请求节流器。

### 6.1 手动刷新服务

集成提供手动刷新服务：

```text
china_gas.refresh_account
```

服务用途：

- 立即刷新指定 China Gas 集成实例。
- 如果不指定目标，刷新所有 China Gas 集成实例。
- 服务调用触发 coordinator 的 `async_request_refresh()`。
- 手动刷新同样执行埋点初始化、token 检查、账号基本信息查询和月度账单查询。

服务定义建议：

```yaml
refresh_account:
  target:
    entity:
      integration: china_gas
  fields:
    force:
      required: false
      default: false
      selector:
        boolean:
```

行为说明：

- 指定任一 China Gas 实体时，通过实体所属 device/config entry 定位对应实例。
- `force: false` 时遵守 Home Assistant coordinator 的刷新节流。
- `force: true` 时绕过节流，立即请求接口。
- token 失效或网络失败时按运行期错误处理规则处理。

## 7. 数据规范化

API 返回大量数字字符串，集成内部需要统一转换：

- 金额字段：转为 `float`，保留 2 位显示由 HA 负责。
- 气量/表底数字段：优先转为 `float`，整数显示由 HA 自动处理。
- 日期字段：
  - `YYYY-MM-DD` 保持 ISO 日期字符串。
  - `YYYYMMDD` 转换为 `YYYY-MM-DD`。
  - `YYYYMM` 可显示为 `YYYY-MM`，原始值保留在属性中。
- 空字符串、`null`、缺失字段统一处理为 `None`。

字段映射示例：

```python
normalized_bill = {
    "record_month": "<YYYY-MM>",
```

## 8. 错误处理

### 8.1 配置阶段

| 错误场景 | 用户提示 |
| --- | --- |
| token 无效 | Token 无效，请重新从中国燃气小程序获取。 |
| 燃气编号或用户名错误 | 未查询到燃气账号，请检查燃气编号和用户名。 |
| 网络超时 | 无法连接中国燃气服务，请稍后重试。 |
| 接口返回结构异常 | 中国燃气接口返回异常，请查看日志。 |

### 8.2 运行阶段

- 网络错误：抛出 `UpdateFailed`，保持上一轮有效数据。
- token 失效：该账号实体标记为 `unavailable`，创建 repair issue。
- 当前实例更新失败：只影响该实例下的实体，不影响用户手动添加的其他 China Gas 实例。
- 当前实例所有请求链路失败：协调器本轮更新失败。
- 日志中必须隐藏：
  - `access_token`
  - `x_mas_app_info`
  - `user_id`
  - 手机号
  - 详细地址

## 12. 当前设计边界

- 不内置登录流程，用户需要自行从中国燃气小程序抓取 token 与请求头信息。
- token 可能过期，集成只负责检测和提示，不负责自动续期。
- 不做缴费、开票、修改用户资料等写操作。
- 账单接口返回的余额字段可能与基本信息接口的 `countMoney` 不一致，主余额以基本信息接口为准，账单接口余额仅作为账单属性保留。
